1. Priority Queue Explanation
A Priority Queue is an Abstract Data Type (ADT) similar to a standard queue, but instead of strictly processing elements in a First-In-First-Out (FIFO) manner, each element is associated with a "key" that denotes its priority. Elements are removed based on their priority (in our implementation, a minimum-oriented priority queue removes the element with the lowest integer key first). The underlying structure used to implement the ADT can vary, such as using an unsorted list, a sorted list, or a heap.

2. Heap Explanation
A Heap is a concrete data structure often used to implement a Priority Queue efficiently. It is a complete binary tree that satisfies the heap-order property: in a min-heap, every node's key is greater than or equal to its parent's key. Because it is a complete tree, a heap can be represented easily inside an array or ArrayList without explicit node pointers. The parent, left child, and right child of any node at index i can be found using simple arithmetic: parent = (i-1)/2, left = 2i+1, and right = 2i+2.

3. Complexity Analysis
For an Unsorted List Priority Queue:

PQ insert: O(1) - Appended directly to the end of the list.

PQ min: O(n) - Must linearly scan the entire list to find the smallest key.

PQ removeMin: O(n) - Must linearly scan to find the smallest key, and then potentially shift elements to remove it.

For a Heap-Based Priority Queue:

PQ insert: O(log n) - Inserted at the end of the array, but then requires upheap which traverses up the tree height (log n).

PQ min: O(1) - The minimum element is always at the root of the tree (index 0 of the array).

PQ removeMin: O(log n) - The root is removed and replaced by the last element in the array, which is then bubbled down via downheap scaling with the tree height (log n).

4. Why Heap removeMin is efficient
In an unsorted list, removing the minimum element requires searching the entire list (O(n)). In a heap, the minimum element is already known to be exactly at the root (index 0), so finding it is O(1). When it is removed, the heap replaces the root with the very last leaf element to maintain the "complete tree" shape. To restore the priority order, the new root is pushed down (downheap) by swapping it with its smallest child. Because the heap is a balanced binary tree, its height is strictly log(n). Therefore, the downheap process takes at most log(n) operations, making removeMin highly efficient (O(log n)) compared to linear structures.
